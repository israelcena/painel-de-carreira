# Automatic rejection runs when a page renders, not on a schedule

Applications that reach the Idle limit are moved to the Rejected Stage by a sweep that runs at the start of rendering the Quadro, Dashboard and Histórico pages, before they read any data, instead of by a scheduled job. The app runs on Vercel and self-hosted with Docker Compose, neither has a scheduler, and with a single user nobody sees the board or the metrics without the sweep having run first. Since the sweep only runs when the app is opened, each Rejection is dated when the Idle limit was reached, not when the sweep ran, so time per Stage, the event date in the History, the days in the Rejected Stage and the recency order of the Rejected lane do not depend on when the app was opened; and each move is a conditional update (only while the Application is still in the Stage it was found in, not Archived, and with the same `updatedAt` the sweep read, so any change since the read, such as a new Next action or an unarchive, leaves the move to the next load) that writes its History event only when it matched, so concurrent page loads cannot reject an Application twice. It is the one Rejection that does not ask for a reason, because the reason is fixed, but it still enters the Rejected Stage as a full Rejection (reason, date, the Stage it came from and a History event), never as a plain move, consistent with ADR-0002. Consequences: any new page that shows Stage-dependent data must run the sweep before reading it; and Vercel previews share the production database (there is no per-preview Neon branch yet), so opening a preview runs the sweep against production data.
